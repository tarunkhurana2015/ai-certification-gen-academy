# Automatic test video implementation plan

> For agentic workers: use subagent-driven-development or executing-plans to implement the tasks below.

**Goal:** Record each manually invoked notebook 21 journey automatically and play the saved video in its HTML report.

**Architecture:** Host-owned recording starts after Appium session creation and before agent invocation. Stop/retrieve in `finally` before closing the driver. Preserve native MOV and use built-in `avconvert` for MP4; JSON/HTML export copies a neighboring video file.

**Tech stack:** Existing Appium XCUITest native recording, Python standard library, macOS `avconvert`, HTML video controls.

**Spec:** User-approved conversation: automatic recording + playback first, screenshots retained, recording errors must not hide test results, no timestamp-seeking feature yet.

## Constraints

- One manually selected scenario; no new LLM calls to record or summarize video.
- Existing Xcode 27/iOS 27 Simulator supports native recording; no FFmpeg install.
- Native recorder returns `{uuid, payload, ...}` with MOV bytes, not MP4 bytes.
- Stop only an owned recording UUID in the same Appium session.
- Capture begins before agent execution, not before session creation or app launch.
- Preserve original movie when conversion fails and label partial/unavailable evidence.
- Keep JSON/HTML result status independent of recording/export status.
- Share HTML and sibling video together; do not embed large video payloads in JSON/HTML.

## Review focus

- Existing recording must never be stopped or overwritten.
- Exceptions and keyboard interrupts must still finalize before driver cleanup.
- Empty/corrupt/oversized media and converter failures must retain diagnostics.
- Partial runs must preserve video while remaining partial runs.
- Export paths must remain inside the configured recordings directory; URLs and traversal are invalid.
